# 演讲时怎么翻 README

英文稿在 `PRESENTATION.txt`，约 639 词。正常偏慢语速大约 5 到 6 分钟；不要逐行念代码。

1. 开场停在 README 顶部。说明自己一个人一组，两个真实项目，两种语言。
2. 翻到 Morningstar 的原代码。指一下 `flashHeal` 和 `flashFull`：都创建文字、往上浮、淡出、最后销毁。重点是重复流程，不是两个消息应该变成一样。
3. 翻到改后代码。指出 `flashMessage` 是共用部分，两个原方法保留各自样式。720 和 420 是毫秒，不必把所有参数念出来。
4. 翻到 TypeScript 的调用处。指一下七个参数，说明阅读调用时要追踪太多上下文。
5. 翻到重构后的 TypeScript 和调用处。说明把相关依赖放进 context，但必须每次读取当前状态，并保留更新 main 中变量的回调。独立示例已经运行验证，没有改原项目。
6. 翻到检查部分。可以运行 `node check-morningstar.mjs` 和 `deno task check`，五个 JavaScript 场景和八个 TypeScript 测试均通过。不能说完整游戏测试已经通过。

## 可能被问到的问题

**为什么重复两次也值得提？**

Because both methods share the same animation lifecycle. A change to that shared behavior needs to stay consistent in both places. The extraction is small, so I think it is worth considering here.

**把参数放进对象，不还是那些数据吗？**

Yes. It doesn't remove the dependencies. It gives them names at the call site and groups them around one operation. If the object becomes a bag of unrelated fields, it hasn't solved much.

**为什么不直接传整个 scene 或整个 app？**

That would make the function depend on more than it needs. I would keep the context limited to pointer movement.

**JavaScript 和 TypeScript 太相似了吧？**

They are closely related. I chose them because these are the languages of the actual projects. The useful difference here is that TypeScript can describe the context and callbacks with types, while JavaScript relies more on runtime checks.

**改了实际游戏吗？**

No. These are isolated study examples and a proposed design. The original projects are unchanged.
