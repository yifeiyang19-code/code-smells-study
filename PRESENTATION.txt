Hi everyone, I'm Jason. I worked individually for this assignment.

I chose two code smells from projects I actually use: Duplicated Code in Morningstar Port, and Long Parameter List in my Sticker Sketchpad. Morningstar uses JavaScript, and the sketchpad uses TypeScript.

I'll start with a small part of Morningstar: the messages above health packs.

When the player collects a pack, the game can show a message like plus two HP. If the player already has full health, it shows HP FULL instead.

Here are the two original methods. They look very similar. Both create text above the pack, center it, set its depth, animate it upward, fade it out, and destroy it at the end.

There are differences worth keeping. The healing message has a larger font and lasts seven hundred and twenty milliseconds. The full-health message is smaller and lasts four hundred and twenty milliseconds.

The duplicated part is the process around those differences. If I want to change the font family or how the text gets cleaned up, I have to remember both methods.

My proposed refactoring is Extract Function, or Extract Method. I keep the two original method names, but have them call a shared method called flashMessage.

In this version, flashHeal and flashFull provide the message and its style. The helper handles creating the text, running the tween, and destroying the text afterward.

I kept the original colors, sizes, positions, and durations. The goal is to make a later change easier while keeping the same feedback on screen.

I also wouldn't turn this into a big effects framework yet. A small helper inside this feature is enough for these two messages.

Now I'll move to the sketchpad.

This function handles pointer movement while drawing. It receives seven arguments: the event, the canvas, the active pointer ID, the current point, the active stroke, a callback to update the point, and a callback to redraw.

The function itself is fairly easy to follow. It ignores the wrong pointer, skips duplicate positions, adds a new point, and redraws. The awkward part is the caller. It has to pass all of that context in the correct order.

I chose Long Parameter List because the arguments make one drawing operation harder to read and extend. The number seven is a clue. The reason to change it is the coordination it requires.

The refactoring is Introduce Parameter Object. In the study version, I pass the event and a named context for pointer movement. That context contains the current drawing state and the callbacks the function needs.

There is a detail I need to be careful about. The drawing state changes while the app runs. If I build the context once when the app starts, it could keep the initial null values. The wrapper builds it for each event so it uses the current stroke and pointer.

I also keep the callback that updates the point in main. Changing a field on a temporary object would not automatically update that original variable.

The README shows the original function and the refactored study version. The original sketchpad application stays unchanged.

For the Morningstar example, I compared the original and extracted versions with a small scene substitute. The check records the text and animation calls, including cleanup. All five cases match. That checks the calls, but I would still need an in-game check before claiming the animation looks right.

For TypeScript, all eight checks pass. These include the wrong pointer, duplicate points, coordinate scaling, and a second event reading the updated point.

What I took from these examples is that working features can still be awkward to maintain. In Morningstar, I would give a repeated animation one implementation. In the sketchpad, I would make the handler's dependencies easier to read. In both cases, I need to preserve the behavior that already works.
